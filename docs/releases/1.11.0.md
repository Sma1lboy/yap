# Yap 1.11.0

Changes since 1.10.0. 中文在下面。

Yap is an open-source (GPL-3.0) dictation app for macOS, forked from VoiceInk. Hold a shortcut, talk in English, Chinese or both in one sentence, and let go: Yap transcribes, cleans up, and pastes. Run it on a local model, with your own provider key, or through Yap Cloud.

## Use your Yap data in Claude Code / Cursor / Codex

- Yap now ships a small read-only MCP server inside the app, `Yap.app/Contents/Helpers/yap-mcp`. Your agent starts it as a subprocess and talks to it over stdin/stdout. It reads Yap's data on this Mac only, opens no network port and sends nothing anywhere. Yap doesn't need to be running.
- Each call copies Yap's local database, reads the copy and deletes it. Yap's own files are only copied: the helper never opens them as a database and never changes them.
- Agents can list your meetings and read one (notes and transcript, the same Markdown as History › Export Markdown), search your dictations and meetings, read a single dictation, and read your dictionary (words and replacement rules). Search matches the words as you typed them, ignoring case and accents, with Chinese and English in one query. It returns 20 results by default and up to 50 when the agent asks, newest first.
- Nothing can be read until you turn it on in the new **Settings › Agent Access (MCP)**. Both of its switches are off on a new install and after this update.
- **Let Agents Read Yap's Data** lets agents read meetings and the dictionary. While it's off, agents can still connect, but every read is an error that tells them which switch to turn on and where.
- **Include Dictation History** adds your dictations. It is a separate switch because dictations go into any app and often hold passwords, private messages and drafts, while meeting notes are written to be shared. It can only be turned on while the first switch is on. While it's off, a search covers meetings only and says that dictations were left out.
- The switches are read again on every call, so turning one off applies to the agent's next request; nothing needs a restart.
- To connect an agent, open the **Connect an Agent** section under the switches. It shows where the helper is in your copy of Yap (with **Show in Finder**), **Copy Command** for Claude Code and Codex, and **Copy JSON** for Cursor's `~/.cursor/mcp.json`, all with the right path. **Learn More** opens the full documentation. Searching Settings for "MCP", "Claude Code", "Codex" or "Cursor" finds it.
- Then ask, for example: "Summarize the action items from this week's meetings", "What did I dictate about the CI migration last month?" (needs Include Dictation History), or "Check this README against the spellings in my Yap dictionary".

## Languages

- In French, the onboarding line about recording meetings now says "Paramètres", the name the Settings page uses, instead of "Réglages".

## Known limits

- Read-only: an agent can't change anything in Yap, for example add a word to the dictionary.
- No meaning-based (vector) search. A search finds the words as they were written: "release" doesn't find a dictation that only says "ship it".
- The agent's app has to support MCP servers that run as a local command (the stdio transport). Clients that can only reach servers over the network can't use it.
- Clients that speak only the newest MCP revision (2026-07-28, which drops the `initialize` handshake) can't connect yet. Clients that fall back to `initialize` work; Claude Code 2.1.284 uses it.
- The switches are the only gate. With "Let Agents Read Yap's Data" on, any program running as you can start the helper and read your meetings and dictionary, just as it could read Yap's files directly. The switches decide what the agents you connected may read; they're not a sandbox.
- Not yet tried on real data: reading a real recorded meeting (only test meetings so far), and a dictionary synced through iCloud.

# Yap 1.11.0（中文）

1.10.0 之后的改动。

Yap 是一个开源（GPL-3.0）的 macOS 听写 app，fork 自 VoiceInk。按住快捷键，用中文、英文或者一句话里中英混着说，松开：Yap 转写、清理，然后粘贴。可以用本机模型、你自己的服务商 key，或者 Yap Cloud。

## 在 Claude Code / Cursor / Codex 里用 Yap 的数据

- Yap 现在在 app 里带了一个只读的 MCP server：`Yap.app/Contents/Helpers/yap-mcp`。agent 把它当子进程启动，通过 stdin/stdout 跟它通信。它只在这台 Mac 上读 Yap 的数据，不开网络端口，不往任何地方发数据。Yap 开不开着都能用。
- 每次调用先把 Yap 的本地数据库拷一份，读拷贝，读完删掉。Yap 自己的文件只被复制：辅助程序从不把它们当数据库打开，也从不改动它们。
- agent 能列出你的会议并读其中一场（纪要和转写，和“历史记录 › 导出 Markdown”导出的一样），在听写和会议里搜索，读某一条听写，以及读你的词典（词和替换规则）。搜索按你写下的字匹配，不分大小写和重音，一句里可以中英混搭。默认返回 20 条，agent 要的话最多 50 条，新的在前。
- 在新的 **设置 › Agent 访问（MCP）** 里打开之前，什么都读不到。新装和这次更新后，这里的两个开关都是关的。
- **让 agent 读取 Yap 的数据**：允许 agent 读会议和词典。关着时 agent 也能连上，但每次读取都会报错，并告诉它该打开哪个开关、在哪。
- **包括听写历史**：再加上你的听写。它单独一个开关，因为听写会打进任何 app，里面常有密码、私信和草稿；会议纪要本来就是写给别人看的。第一个开关打开时才能打开它。关着时搜索只搜会议，并说明听写没有包括在内。
- 每次调用都重新读这两个开关，所以关掉之后 agent 的下一次请求就读不到了，不用重启任何东西。
- 连接 agent：开关下面的 **连接 agent** 分组显示你这份 Yap 里辅助程序的位置（带“在 Finder 中显示”），Claude Code 和 Codex 有“复制命令”，Cursor 的 `~/.cursor/mcp.json` 有“复制 JSON”，路径都已经填好。“了解更多”打开完整文档。在设置里搜“MCP”“Claude Code”“Codex”或“Cursor”都能找到这里。
- 然后可以问：“总结一下这周会议里的待办”“上个月我听写过哪些关于 CI 迁移的内容？”（需要打开“包括听写历史”）“按我 Yap 词典里的拼写检查这份 README”。

## 语言

- 法语界面下，引导里关于录制会议的那句现在写“Paramètres”（设置页面在法语里的名字），不再是“Réglages”。

## 已知限制

- 只读：agent 不能改 Yap 里的任何东西，比如往词典里加词。
- 没有按意思（向量）搜索。搜索只找写下来的字：搜“发布”找不到只说了“上线”的听写。
- agent 所在的 app 要支持以本机命令方式运行的 MCP server（stdio 传输）。只能通过网络连接 server 的客户端用不了。
- 只支持最新 MCP 协议版本（2026-07-28，去掉了 `initialize` 握手）的客户端暂时连不上。会退回用 `initialize` 的客户端可以；Claude Code 2.1.284 用的就是它。
- 开关是唯一的关口。打开“让 agent 读取 Yap 的数据”后，以你的身份运行的任何程序都能启动辅助程序，读你的会议和词典，就像它本来也能直接读 Yap 的文件一样。开关管的是你连上的 agent 能读什么，它不是沙盒。
- 还没在真实数据上试过：读一场真实录制的会议（目前只用测试会议试过），以及通过 iCloud 同步的词典。
